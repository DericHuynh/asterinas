# Ext4 feature expansion: implementation and proof ledger

This branch adds executable feature components and their Verus contracts. The certified parent source at commit `5b48f3ec9beb62c5a4220f45e30a779e1b18ce80` passed the unchanged official unfiltered strict check and compilation: **5,481 obligations, zero errors**, including **985 named proofs and 1,249 public executable APIs across 258 source files**. This checks the declared host models and executable core; it does not establish complete ext4 features or a mounted filesystem.

This extension adds numeric filesystem geometry with **29 focused obligations, zero errors**, and **1,225 numeric cases, five privacy rejections and one allowed control** against its actual focused-compiled library. The current **259-source** registry has not passed a new whole-crate check; the parent certificate below covers its original 258 sources. See [FS_GEOMETRY.md](FS_GEOMETRY.md) for exact hashes, scope and reproduction.

The official compatibility suite passes 372 host tests and 376 API rejection cases against this exact checked artifact. These are runtime/API checks, not formal proof. Fresh negative gate checks: passed; timeout regression: passed.

The prior whole-crate baseline at commit `9083e1d36cb433927df6c0b636c8377a4c350c22` checked 3,142 obligations, 915 named proofs and 775 executable APIs. Its 372 native tests and 340 API rejection cases remain historical evidence for those bytes. Focused checks, compile-only diagnostics, native oracles and superseded snapshots retain their exact original source/artifact scope in the ledger.

The existing full-feature and mount gates remain closed. A completed codec, numeric protocol or test image does not authorize a mounted operation.

## Completion criteria

Each row needs exact source/format refinement, total public APIs, ownership and concurrency invariants, crash and restart closure where relevant, Linux image interoperability, negative API tests and a strict whole-crate proof against the locked source inventory. Mounted support additionally requires composition across allocator, namespace, quota, orphan, crypto and device layers.

Numeric identifiers and modeled completion events do not confer device, inode, frame, allocation or credential authority. BIO completion and 512-byte sector metadata do not establish 4 KiB failure atomicity or power-loss durability. Those premises must be supplied by the runtime boundary before writable admission.
